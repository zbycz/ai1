📋 Esence refactoringu (zadání pro agenta)

Klíčový vzor: Eliminace "prop drilling" odvozených hodnot — přesun výpočtu derived state z nadřazené (orchestrující) komponenty přímo do podkomponent, které je potřebují.

1. Prop drilling → lokální hooks

Komponenta CragsInAreaInner počítala odvozené hodnoty a předávala je jako props dolů:

  • numberOfRoutes (reduce přes crags) → přesunuto do AreaInfo
  • otherFeatures (filter na memberFeatures) → přesunuto do CragList
  • numberOfHiddenCrags (diff délky polí) → přesunuto do NumberOfHiddenCrags
  • allCragRoutes (reduce přes crags) → přesunuto do nové AllCragsDistribution
  • feature (z useFeatureContext) → podkomponenty volají hook samy

2. Smart components – null-return pattern

Komponenty samy rozhodují, zda mají co vyrenderovat. Místo aby parent dělal podmíněný rendering (count > 0 && <NumberOfHiddenCrags count={count} />), komponenta si sama zjistí hodnotu a vrátí null když nemá co zobrazit.

3. Extrakce nových pojmenovaných sub-komponent

  • FilterRow — wrapper React.FC pro StyledPaper + Stack s filtry
  • AllCragsDistribution — extrakce podmíněného bloku {crags.length > 1 && <RouteDistribution .../>}

4. TypeScript zpřísnění props

Props rozhraní se zpřesnila — komponenty přijímají jen minimum nutných dat ({ crags: Feature[] }) a vše ostatní si odvozují samy přes hooks.

5. Čistší JSX v CragsInAreaInner

Po refactoringu je CragsInAreaInner minimální — pouze získá filtrovaný+setřízený seznam cragů a předá ho dál. Zanořené ? ... : null nahrazeno &&.
